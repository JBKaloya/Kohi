# Kohi — Notes de build

**Date** : 14 septembre 2026 · **Version** : 1.0 (3) · **Cible** : iPhone, iOS 18.0+

Ce document décrit le build tel qu'il sort de la machine aujourd'hui : ce qui compile, ce qui est embarqué, ce qui dépend d'une configuration, et ce qui n'est pas là. Le détail fonctionnel écran par écran vit dans [fonctionnalites.md](fonctionnalites.md). Le guide à donner aux testeurs est [guide-de-test.md](guide-de-test.md).

---

Certaines surfaces sont conditionnées à iOS 26 (transition zoom de la grille vers le détail, `SpeechAnalyzer` pour la dictée). Sur iOS 18–25 l'app fonctionne, avec un repli : transition standard, `SFSpeechRecognizer` pour la dictée.

## 2. État de vérification

```
xcodebuild -scheme Kohi -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -configuration Debug build
** BUILD SUCCEEDED **

xcodebuild test -scheme Kohi -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -configuration Debug
Test run with 349 tests in 34 suites passed
** TEST SUCCEEDED **
```

Aucun warning bloquant, aucun test rouge. Les suites couvrent le parsing (OCR, sachet, recette, dictée), les règles de recette et de diagnostic, la mise à l'échelle, la comparabilité des brews, la roue des saveurs, la parité de schéma sync, et des snapshots de glyphes.

## 3. Permissions demandées

Aucune n'est demandée au lancement. Chacune arrive au moment où l'utilisateur déclenche la fonction.

| Permission | Déclencheur | Texte affiché |
| --- | --- | --- |
| Caméra | Bouton scan | « Kohi uses the camera to scan coffee cards. » |
| Micro | **Say it** (dictée) | « So you can say what you brewed instead of typing it. Recording stops the moment you tap again. » |
| Reconnaissance vocale | **Say it** (dictée) | « Speech is turned into text on this phone. Nothing you say is sent anywhere. » |
| Localisation (en usage) | Recherche de lieu | « Kohi uses your location to put nearby coffee shops and roasters at the top of the place search. » |

Le refus de la caméra ne bloque pas l'ajout : l'écran de scan propose encore **Photo** (photothèque) et **Demo** (carte d'exemple).

### Archive d'échantillon

Au **tout premier lancement** (fichier `cards.json` absent), en Debug **comme en Release**, l'app pose **6 cartes d'exemple** avec leurs images : Kenya Tekangu, Chelbesa, El Paraíso Lychee, El Injerto Pacamara, Hartmann Geisha, Fazenda Sertão.

Ces cartes arrivent **sans brew et sans kit déclaré**. Conséquence directe pour les tests : l'onglet *Suggested* et la section *Profile* d'une carte ne se remplissent qu'après que le testeur a logué des extractions.

### Police et assets

`AngustaTest-DemiBold.otf` est embarquée (`UIAppFonts`), plus les 6 images d'échantillon et l'icône d'app.

## 5. Configuration cloud

Le fichier `Kohi/Resources/Supabase.plist` (`SUPABASE_URL` + `SUPABASE_KEY`) est **présent dans l'arbre de travail local mais ignoré par git**. Un gabarit est versionné : `Supabase.example.plist`.

| Sans `Supabase.plist` | Avec `Supabase.plist` |
| --- | --- |
| Scan, OCR Vision local, règles, recettes de référence, kit, archive, dictée on-device | Idem, plus : |
| Pas de rangée **Account** dans Profil | Sign in with Apple + sync bidirectionnelle |
| Pas de choix **AI flyer** à la création d'une carte | Posters 4:5 générés par `card-poster` |
| Pas de **Read again with AI** | Second avis `card-vision` sur les lectures faibles |
| Pas de **Ask**, pas de variante de recette, pas de repli de dictée serveur | `ask`, `recipe-adapt`, `field-extract` |

**À décider avant de distribuer un build** : si le `.plist` est dans le bundle envoyé aux testeurs, ils tapent sur le projet Supabase réel et les appels IA sont facturés. S'il est retiré, tout le lot IA et le compte disparaissent de l'UI, et le guide de test doit sauter les parcours 8 et 9.

## 6. Drapeaux et valeurs par défaut

### Surfaces lot 2 — `LotFlags`, Profil › *Surfaces*

Le seeding des défauts se fait **une seule fois, au premier lancement**. Changer de configuration après coup ne les réinitialise pas.

| Drapeau | Libellé | Debug | Release | Ce qui disparaît quand il est off |
| --- | --- | --- | --- | --- |
| `brewCompare` | Brew compare | **on** | **on** (purgé par `lot2.surfaces.reset`) | *Compare with…* |
| `cardProfile` | Card profile | **on** | **on** (purgé par `lot2.surfaces.reset`) | La section *Profile* d'une carte |
| `flavorOrigin` | Aroma origin in diagnosis | **off** | **off** | Les classes d'origine dans le diagnostic |
| `keepVoiceNote` | Keep brew recordings | **off** | **off** | L'audio de la note de brew est conservé |

Taste (7 axes) et la roue aromatique ne sont plus des flags : ils sont toujours montés. Les anciens `taste7` / `flavorWheel` encore présents dans `lot2.disabled` sont purgés une fois par `lot2.surfaces.reset`.

Override en Debug : `KOHI_BREW_COMPARE`, `KOHI_CARD_PROFILE`, `KOHI_FLAVOR_ORIGIN`, `KOHI_KEEP_VOICE_NOTE` (`0` = off).

### IA — `AIFlags`, Profil › *Experimental AI*

Deux interrupteurs en série : celui de l'utilisateur, et celui du serveur (table `ai_flags`, qui permet d'éteindre une feature sur un build déjà installé).

| Feature | Libellé | Expérimental ? | État au premier lancement |
| --- | --- | --- | --- |
| `cardVision` | Read labels | non | **on** |
| `poster` | Make flyers | non | **on** |
| `fieldExtract` | Understand dictation | oui | off (master off) |
| `recipeAdapt` | Suggest recipe variants | oui | off (master off) |
| `ask` | Answer questions | oui | off (master off) |

Le master **Experimental AI** est **off par défaut**. `cardVision` et `poster` ne sont pas derrière lui : ils tournent dès que Supabase est configuré.

Chaque appel écrit un `AIEvent` (feature, modèle, tokens, latence, accepté ou non). Profil affiche un résumé « Kept ».

### Hooks de développement — Debug seulement

Via l'environnement enfant du simulateur (`SIMCTL_CHILD_…`) ou le schéma Xcode :

| Variable | Effet |
| --- | --- |
| `KOHI_EMPTY=1` | Pas de seeding — pour voir l'état vide |
| `KOHI_AUTOSCAN=1` | Dépose un scan d'échantillon au lancement |
| `KOHI_REVIEW=1` | Ouvre le flux de scan directement sur l'étape de revue |
| `KOHI_OPEN_FIRST=1` | Ouvre la carte la plus récente après 1 s |
| `KOHI_BULK=<n>` | Gonfle l'archive à `n` cartes (mesure de scroll) |
| `KOHI_MIGRATION_REPORT=1` | Loggue le rapport de migration lot 2 |

Profil expose aussi une section **Developer** en Debug uniquement : *Run onboarding*, *Reset first-scan flag*, *Reset kit*.

## 7. Backend

Migrations Supabase à jour jusqu'à `0014_brew_scale.sql`. Cinq edge functions déployables : `card-vision`, `card-poster`, `field-extract`, `recipe-adapt`, `ask`.

La table `knowledge` qui alimente **Ask** est **créée mais vide**. Ask répondra donc « The base does not cover this one. » sur la plupart des questions. C'est attendu, pas un bug — à dire aux testeurs.

## 8. Limites connues de ce build

Rien de ce qui suit n'est un bug. Ce sont des décisions datées, à ne pas faire remonter comme des défauts.

| Sujet | État |
| --- | --- |
| Rosace / lotus du timer guidé | Absent — les étapes fonctionnent, la représentation circulaire non |
| Scan IA du sachet / ticket / étiquette d'eau | Code présent, UI absente. Ces pièces jointes passent par l'OCR local seul |
| Ask contextualisé (carte, kit, 3 derniers brews) | Absent — Ask est une feuille isolée |
| Base de connaissances `knowledge` | 0 ligne |
| Seed torréfacteurs | Absent — l'index se remplit à l'usage |
| Share Extension, widget, Control Center | Absents |
| Identification d'équipement par photo | Absent (rangée « soon » dans Profil) |
| Import iBrewCoffee / export d'archive | Absents (rangées « soon ») |
| Vue torréfacteur (tap sur un nom → ses cartes) | Absent |
| Recette de référence A4 Switch | Manquante — 15 recettes au lieu des 16 prévues |
| Thème sombre, iPad, Mac, partage social | Non-objectifs assumés |

L'écart complet avec le PRD est tabulé dans [fonctionnalites.md](fonctionnalites.md#écart-avec-le-prd-v1).

## 9. Construire et lancer

Xcode 26.x requis. Aucune dépendance à installer à la main : `supabase-swift` et `swift-snapshot-testing` sont résolus par SPM au premier build.

```sh
# Build
xcodebuild -scheme Kohi \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -configuration Debug build

# Tests
xcodebuild test -scheme Kohi \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -configuration Debug
```

Pour partir d'une archive vierge sur simulateur, effacer le contenu du simulateur ou lancer avec `SIMCTL_CHILD_KOHI_EMPTY=1`. Sur un appareil, désinstaller l'app suffit : tout l'état (archive, images, kit, recettes, drapeaux) part avec elle.
